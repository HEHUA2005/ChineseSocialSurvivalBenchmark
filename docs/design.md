# 设计文档：老中人情世故 Benchmark

## 1. 为什么做这个 benchmark

现有中文基准（CMMLU、C-Eval 等）测知识储备，不测**社会判断力**。而大模型在中文社交场景中最常犯的错不是"不知道"，而是"不会做人"：过于坦诚、字面理解潜台词、把客套话当真、公开场合不给面子。人情世故 benchmark 专门量化这种能力。

**核心假设**：人情世故 = 情境理解 × 分寸感 × 表达方式。三者缺一，都会在题目上现形。

## 2. 题型设计

| 题型 | 占比目标 | 评测方式 | 优势 |
|---|---|---|---|
| 选择题（MC） | ~60% | 自动判分，客观可复现 | 大规模、低成本、可分组统计 |
| 开放题 | ~30% | LLM-as-judge 按 rubric 打分 | 测表达能力与理由深度，无法蒙 |
| 多轮对话（规划中） | ~10% | judge 评价 | 测"说到做到"、临场应变 |

## 3. 全自动流水线（零人工标注）

```
生成(grok-4.3-fast) ──► 质检(独立判官×2 + 综合评审×2采样) ──► 正式集 ──► 评测(deepseek)
    30 题原创情境        淘汰率 ~63%（19/30 被过滤）              11 题         90.9% MC
```

### 3.1 生成（src/generate.py）
- **防污染**：prompt 里不给任何"参考答案样例"，只给维度描述 + 情境关键词种子，强制原创场景
- **选项梯度**：要求 4 个选项有明确情商梯度（得体 / 诚实但傻 / 油滑 / 失礼），且不能写得太假
- **评判标准内化**：让生成器遵循"①安全 ②真实 ③长远"的优先级，同时警惕"过犹不及"

### 3.2 质检（src/validate.py）—— 用 LLM 对抗 LLM
三道防线：
1. **独立判官**：judge 不看到标定答案，独立作答。judge 选的和标定答案不一致 → "有争议"淘汰（本轮 30 题中约半数死在这一关，说明生成器的"答案"经常并非唯一最优）
2. **综合评审**：5 维度打分（答案唯一性/选项质量/题干质量/文化适切/过犹不及），多轮采样取**保守结果**（全部轮次 pass 才收录）
3. **共识度标注**：judge 预估"主流中国人认同比例"，<0.6 淘汰

### 3.3 评测（src/evaluate.py）
- **客观题**：自动判分 + 按维度分组统计 + 可选多次采样测**答题稳定性**
- **开放题**：rubric 5 维（得体性/分寸感/可行性/长远性/理由充分性），0~50 分

## 4. 初步结果与分析（deepseek-v4-flash-free）

| 指标 | 结果 |
|---|---|
| 选择题准确率 | 90.9% (10/11)，两轮一致 |
| 答题稳定性 | 存在摇摆：两轮各错 1 题但错的题不同 |
| 开放题平均 | 进行中 |

### 值得注意的案例

**案例 1：面子文化-001（deepseek 答错）**
> 群管理员 vs 发广告的老同学。主流答案（共识度 0.9）= 私聊处理留面子；deepseek 选"公开调侃"。
> 启示：deepseek 的"幽默化解"思路偏年轻化/偏西方"轻松沟通"文化，与主流中国式"私下解决、公开留面"存在偏差。

**案例 2：职场潜规则-001（deepseek 答错，且标准答案本身有争议）**
> 新人对领导"你觉得这任务怎样"的回复。标准答案=婉拒让资深同事来；deepseek 选"表决心"。
> 启示：该题 A/D 都说得通，说明即使经过双判官验证，"人情世故"仍存在可辩护的分歧。这类题保留（有共识度标注兜底），但应在报告中标记争议度。

## 5. 已知局限与下一步

- **自产自销风险**：生成与质检用同一模型族（grok），可能系统性偏好。下一步用不同模型交叉质检（如 deepseek 生成 → grok 质检）。
- **judge 噪声**：已用多轮采样缓解（校准显示高分样本复打 σ≈2/50，低分样本有+5~8 分的回归上偏——judge 倾向给中间分，这会让低分差距被压缩）。仍需人工抽样验证与人类评分的相关性。
- **题目量**：v1.0 正式集 208 题（113 客观+45 陷阱+50 开放）+ 12 排序 + 9 多轮。已松开规模化瓶颈（生成/质检均批量并行），可扩展到千题级。
- **多轮对话**：已实现（judge 扮演对手 3 轮动态博弈）。局限：judge 同时演对手+裁判，对手反应质量影响终局分；后续可让不同模型轮流演对手。

## 6. 新题型设计（v1.1）

### ① 排序题（杀伤力排序）
场景 + 5 个回应（都不得体但程度不同），要求模型排出「最不得罪→最得罪」。
- 生成：prompt 内嵌 5 个回应的得罪分（1~10），自检单调性；**后端打散字母映射**，防止模型靠位置猜（首字母分布均衡验证）。
- 质检：判官只验证两端点（最轻/最重），不要求完整排序（5! 主观性太强）。两端点一致率约 40% 入册。
- 评测：Kendall tau + 头名准确率 + **底线保护率**（最得罪项被排最后 = 知道什么话不能说）。

### ② 话外音识别（主语感）
对话场景中一句话表面意思 ≠ 真实意图，考「听话听音」。
- 生成：**答案字母轮换**（A/B/C/D 循环打散），实测各字母出现频次完全均衡。
- 质检：判官独立猜真实意图再与标注比对，判官猜不同即淘汰（10/16 入册）。
- 实现为 subtype:spot 并入客观题 pipeline，零额外评测代码。

### ③ 多轮对话博弈
3 轮升级式剧情：judge 扮演对方角色逐轮回应，局面分值 -5~+5 随主角表现升降，踩雷即 trap_triggered。
- 评测指标：终局面分 100 制 + 踩雷率。局面分记录完整轨迹（如 0→3→-3）。

### ④ Judge 自一致性校准（judge_calib）
同一答案 × 3 温度 × 2 次复打，输出：单答案波动 σ、温度极差、整体已测样本散布。
- v1.0 实测：高分答案 σ≈2/50 稳定；低分答案被复打高估 5~8 分（回归效应）→ 建议所有榜单结论关注「相对差值」而非绝对分。

### ⑤ 错题本（hardest）
聚合多模型错题统计 → 提炼「分水岭题」→ 基于结构变体生成（换人设/场合/保留陷阱）。防「答案位置作弊」已在生成期解决（spot 轮换、sort 打散）。

## 7. 使用方式

```bash
# 生成（可指定维度/数量/模型）
python3 -m src.generate --dimension "职场潜规则" --count 5 --model grok-4.3-fast

# 质检（全量）
python3 -m src.validate --all --model grok-4.3-fast

# 评测（客观题 + 稳定性）
python3 -m src.evaluate --model deepseek-v4-flash-free --tag v1 --runs 2

# 评测（含开放题，judge 用 grok）
python3 -m src.evaluate --model deepseek-v4-flash-free --tag v1 --judge-model grok-4.3-fast

# 全题型 × 全模型批量评测
bash scripts/run_all_eval.sh          # 阶段1~5 依次执行
```
